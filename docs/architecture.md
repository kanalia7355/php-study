# PHP Study Quest — 設計

## 基本方針
既存18章の教材・演習・解答を保持する。学習者がworkspaceに実装し、Gitのcommit/pushで保存する。AIによるworkspaceの解答作成、空コミットは行わない。課題の合格は採点成功後にのみ記録する。

## 構成と責務
- `chapters/`, `exercises/`, `solutions/`: 元のNotebook。破損JSONのみ内容を保って修復。
- `curriculum/inventory.json`: 原教材との対応。18章・基本104課題＋第18章発展1課題。第8章の小問は親課題にまとめる。
- `workspace/<課題ID>/`: 学習者が編集するPHPファイル。初期状態は未実装。
- `tests/<章>/<課題ID>.php`: 振る舞い・型・境界値等を検証。見本出力だけの比較を避ける。
- `scripts/quest.php`: ローカルとCI共通の採点CLI。進捗への書込み権限を持たない。
- `progress/`: 正規化された合格イベントとREADME生成器。課題ID・採点対象SHA・提出ファイルのハッシュを記録。

## 実行環境
PHP 8.3、Composer 2、mbstring/PDO。DB課題は原教材のMySQL方言を維持しMySQL 8の隔離テストDBを使用する。フォームはPHP組込みHTTPサーバーに実際のリクエストを送り、セッション・CSRF・multipartを検証する。

## 課題と判定
IDは`ch01-ex01`から`ch18-ex05`、発展は`ch18-extra01`。複数の小問がある課題は全小問の成功で1合格。任意の名前や趣味等は固定値を強制しない。型・変数・表示内容の整合を調べる。既存解答の誤りを合格基準にせず、問題文の要件を優先する。

## CIと保存
PRは読取り専用でシステムのテストと提出の採点を実行する。未提出の課題はskip、提出した未完成の課題はfail。採点結果と進捗書込みを別ジョブに分離し、学習者PHPの実行環境に書込みトークンを渡さない。

mainへのpushで採点された合格だけを保存する。書込みジョブは最小の`contents: write`、PRでは実行しない。保存を直列化し、最新の履歴へ集合和で追加する。失敗・再実行で既存合格を削除しない。採点SHAは元の学習者コミットを保ち、自動更新SHAを学習者の成果と混同しない。README更新に`[skip ci]`を付け、ボット更新とprogress/READMEのみの変更を採点対象外にする。

## 検証のゲート
第1章の合格・誤答・再提出とCLIを検証してから第2章へ進む。18章すべてのテスト、正答/誤答、HTTP/DB、進捗競合を検証し、独立レビューを完了するまでmainにマージしない。
